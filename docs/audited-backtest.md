# Audited portfolio backtest

Run from the repository root:

```powershell
python -m tradingagents.audited_backtest --prices prices.csv --signals signals.json --audits audits.json --diagnostic diagnostic.json --report quantstats.html
```

`prices.csv` has a `date` column and one column per ticker, with daily closes.
`signals.json` is a nonempty array of supplied signals, for example:

```json
[{"date":"2025-01-01","ticker":"BTC-USD","rating":"Buy"}]
```

`audits.json` is an array with one entry per signal's ticker and date. All timestamps
must include a timezone. Candle `open_time` and `available_at` must describe actual
records, and event `published_at` and `available_at` must describe when each event
was published and available. The following shows the format, not real market data:

```json
[{"ticker":"BTC-USD","date":"2025-01-01",
  "start":"2024-12-31T00:00:00Z","decision_time":"2025-01-01T00:00:00Z",
  "candle_interval_seconds":86400,
  "candles":[{"open_time":"2024-12-31T00:00:00Z","available_at":"2025-01-01T00:00:00Z"}],
  "sources":{"news":[],"macro":[],"sentiment":[]}}]
```

The command writes a JSON diagnostic and exits with code 2 unless every signal
has verified complete coverage. Currently the underlying audit cannot establish
complete news, macro or sentiment coverage from event records: it returns
`unknown` or `incomplete`, so the gate always blocks. There is no bypass and no
portfolio or QuantStats report is generated until independent coverage evidence
can be verified. The diagnostic checks timestamps; it does not verify the prices
against the candle records or establish their provenance. It does not generate
signals or place orders.

When a future independent verification can pass this gate, the existing simulator
uses 1,000 initial cash units, a 10% position target and a 0.36% taker fee per
side. Fills use the next supplied daily close, with no slippage or liquidity
model. If both `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID` are configured, the
completed QuantStats report is sent to that chat; notifications do not affect
the simulation.

Yahoo's USD prices are reference prices, not Bitso USDC fills. The current
Bitso taker fee is a historical assumption, not a reconstruction of past fees.
The simulator is long-only and supports consecutive daily cryptocurrency prices;
it does not simulate forex, ETF calendars, spreads, liquidity or slippage.
The native TradingAgents HTML report is generated by TradingAgents separately.

For local use, install the project with `pip install -e '.[backtest]'`. The
repository's `.env` is ignored by Git. Set `FRED_API_KEY` there to use FRED,
and use new private credentials for `TELEGRAM_BOT_TOKEN` and `TELEGRAM_CHAT_ID`.
Never commit credentials. The provided example is illustrative, not evidence.

## Local model

The local runtime and GGUF are not part of this repository. Set `SPARK_MODEL`
to the GGUF path and start the CUDA build downloaded next to this repository:

```powershell
& '..\llama-cuda\llama-server.exe' -m $env:SPARK_MODEL --host 127.0.0.1 --port 8080 --ctx-size 32768 --n-gpu-layers 99 --parallel 1 --reasoning off
```

For TradingAgents, select provider `openai_compatible`, URL
`http://127.0.0.1:8080/v1`, and model `Spark-X2.6-4B`. The server above has no
authentication; use it only while needed and stop it after the test. A graph
may still request more context or return invalid structured output. An aborted
or malformed run must never be treated as a trading decision.
